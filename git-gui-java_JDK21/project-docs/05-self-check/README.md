# Self-Check — 代码自检体系

> 本目录定义 git-gui 桌面应用的代码自检规范和流程，提供由 AI 代理执行的全量代码质量审查能力。自检是门禁检查的补充，侧重人工审查维度（注释、文档一致性、设计原则等）。

---

```plaintext

    └── 自检报告_YYYYMMDD_HHmmss.md  # 按时间戳命名，每份报告对应一次完整自检
```

## 自检规范概述

自检覆盖项目的全部顶层目录，递归检查每一个文件：

- `.trae/` — Trae IDE 规则与配置
- `project-docs/` — 文档与规约
- `app-backend/` — JavaFX 应用代码（Java + FXML + CSS）+ Flyway 迁移脚本（`src/main/resources/db/migration/`）

排除：`target/` `build/` `dist/` `.git/` `.idea/` `.vscode/` `*.min.js` `*.min.css` 二进制文件 `00-temp/`。

### 检查维度

| 类别 | 代码 | 内容 | 严重程度 |
| ---- | ---- | ---- | ------- |
| 文字与文档 | A | 错别字、注释一致性、文档与实现匹配 | P2 |
| 代码注释 | B | 各类语言注释规范（Java Javadoc / FXML 注释 / CSS 注释 / SQL COMMENT / 配置注释），全部使用中文 | P1~P2 |
| 代码质量 | C | 命名规范、冗余清理、硬编码、逻辑健壮性、格式规范 | P1~P2 |
| 安全 | D | 注入防护、敏感信息、输入校验、路径安全、命令红线一致性 | P0~P1 |
| 性能 | E | 资源管理、可复用逻辑、JavaFX 线程规范（禁 UI 线程跑 Git） | P1~P2 |
| 设计原则 | F | SOLID 五项原则（SRP / OCP / DIP / ISP / LSP），Java 文件重点检查 | P1~P2 |
| 跨目录一致性 | G | 文档↔实现一致、spec↔UI ViewModel↔领域 Model 对齐、死链检测、目录结构一致、文件命名规范 | — |

### 严重程度定义

| 级别 | 含义 |
| ---- | ---- |
| P0 | 编译失败、安全漏洞、数据丢失 |
| P1 | 功能异常、逻辑错误、性能隐患、文档与实现矛盾 |
| P2 | 代码风格、命名、注释、格式问题 |
| P3 | 最佳实践建议、可读性改进 |

## 使用方式

### 执行自检

将 `self-check-prompt.txt` 的内容复制给 AI 代理（Claude / Code Buddy / Trae 等），AI 将自动执行以下流程：

1. 确认编译/测试状态（门禁）
2. 对每个范围目录递归遍历所有文件
3. 逐文件加载内容，按 A~F 清单逐项检查
4. 全部文件检查完毕后执行 G 类跨目录一致性检查
5. 汇总并以标准格式输出报告

### 门禁要求

每次自检开始前，需确认以下门禁通过：

- `mvn compile` 通过
- `mvn test` 通过（不跳过测试，TestFX 用 headless 模式）

### 二次自检

自检提示词中内置"二次自检"要求：发现的问题必须先交叉验证，确认是确确实实的问题后才写入报告，避免将误报提交给开发者。

## 自检报告

### 命名规则

报告文件命名格式：`自检报告_YYYYMMDD_HHmmss.md`

使用 PowerShell 命令获取时间戳：

```powershell
Get-Date -Format "yyyyMMdd_HHmmss"
```

### 报告内容

每份报告包含：

- 时间戳与检查范围声明
- 门禁状态汇总
- 按 P0/P1/P2/P3 分级的统计概览（含与上次报告的差异对比）
- 逐条问题清单（编号、文件位置、检查项、问题描述、修复建议）
- 修复优先级建议
- 一键修复指令（可直接复制给 AI 批量修复）

## 与其他体系的关系

自检是质量保障体系的一部分，与以下机制互补：

- **编译/类型检查**（`mvn compile`）：自动化门禁，覆盖语法错误
- **单元测试与 UI 测试**（`mvn test`，JUnit5 + TestFX）：覆盖业务逻辑与界面正确性
- **自检**（本目录）：覆盖注释质量、文档一致性、设计原则等 AI 审查维度

自检定位为"补充检查"，不替代测试和编译检查。三者在 CI/CD 流程中的顺序为：编译检查 → 测试 → 自检报告（可选）。
