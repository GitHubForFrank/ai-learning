## 一、整体分层架构

桌面应用为单 `app-backend/` 模块，UI 与后端同模块但严格 DDD 分层：

```plaintext
┌──────────────────────────────────────────────────┐
│  UI 层   ui/controller/  +  ui/fxml/  +  ui/view/│  JavaFX Controller + FXML + ViewModel
└───────────────────┬──────────────────────────────┘
                    ↓ Guice 注入服务接口
┌──────────────────────────────────────────────────┐
│  应用层  application/service/                    │  用例编排、事务边界、调用红线拦截器
│          application/async/                      │  TaskManager / ProgressCallback
└───────────────────┬──────────────────────────────┘
                    ↓ Domain Model
┌──────────────────────────────────────────────────┐
│  领域层  domain/model/  +  domain/repository/    │  纯 POJO + 仓储接口
│          domain/service/                         │  服务接口契约
│          domain/redline/                         │  红线规则领域
└───────────────────┬──────────────────────────────┘
                    ↓ Guice 绑定（接口 → 实现）
┌──────────────────────────────────────────────────┐
│  基础设施层  infrastructure/cli/                 │  Git CLI 适配器
│              infrastructure/persistence/         │  SQLite 仓储实现 + Flyway
│              infrastructure/credential/          │  系统 credential helper
└───────────────────┬──────────────────────────────┘
                    ↓ 进程 / SQL
                  {Git 仓库} / {SQLite}
```

## 二、模块划分

- `app-backend/`：JavaFX 应用单模块（独立 pom，artifactId=git-gui，无 parent），内部分四层（UI / 应用 / 领域 / 基础设施），并承载 Flyway 迁移脚本（`src/main/resources/db/migration/`，V1~V7）与启动脚本（`scripts/git-gui.bat` / `git-gui.sh`）
- `project-docs/`：文档与规约体系

## 三、关键流程

### 3.1 Commit 流程

```plaintext
UI CommitDialog
  → 收集勾选文件 + commit message（BR-06/BR-07）
  → CommandInterceptor 拦截（敏感文件扫描 BR-32）
  → AsyncTaskService 提交（异步任务 BR-33）
  → CliGitExecutor.commit()
  → OperationLogService.record()（BR-35）
  → EventBus 发 TaskFinishedEvent
  → UI 刷新状态列表
```

### 3.2 Push 流程（含命令红线闭环）

```plaintext
UI PushDialog
  → 选择 remote / branch / 选项（BR-09）
  → CommandInterceptor 调 CommandRedLineService.check()（BR-10）
      ├─ BLOCK  → 拒绝 + 提示安全等价命令 + 记录 audit_log(BLOCKED)（BR-26/BR-31）
      ├─ CONFIRM → UI 弹 RedLineConfirmDialog（BR-29）
      │            ├─ 用户确认 → 记录 audit_log(CONFIRMED) → 继续
      │            └─ 用户取消 → 记录 audit_log(CANCELLED) → 终止
      └─ PASS   → 放行
  → AsyncTaskService 提交（BR-33）
  → CliGitExecutor.push(ProgressCallback)
  → OperationLogService.record() + AuditLog 记录
  → UI 刷新
```

### 3.3 命令红线拦截流程

```plaintext
GitOperationService 写方法
  → CommandInterceptor 拦截
  → 构造 RedLineContext（operation/command/repoPath/branch/remoteUrl/stagedFiles/...）
  → 遍历 Multibindings<RedLineRule>（13 个规则）
      ├─ 任一 BLOCK  → 返回 BLOCK（拒绝）
      ├─ 任一 CONFIRM → 收集确认项
      └─ 全部 PASS   → 返回 PASS
  → 返回 RedLineResult
  → UI 据 action 放行 / 弹窗 / 拒绝
  → CommandRedLineService.recordAudit()（BR-31）
```

### 3.4 异步任务流程

```plaintext
UI 调服务
  → 服务包装为 TaskRequest
  → TaskManager 排队（同仓库写串行 BR-34，读并发）
  → 提交 JavaFX Task
  → CLI 执行（ProgressCallback 实时反馈）
  → 持久化 task_record + operation_log（BR-35）
  → EventBus 发 TaskFinishedEvent
  → UI 用 Platform.runLater() 刷新（BR-36）
```

## 四、Guice 绑定结构

| Module | 绑定内容 |
| ------ | ------ |
| `AppModule` | 核心常量、路径、异常处理器 |
| `DatabaseModule` | DataSource、Flyway、Repository 接口 → 实现 |
| `GitModule` | `CliGitExecutor`、`GitProcessBuilder`、`SystemCredentialHelper` |
| `ServiceModule` | `domain/service/*` 接口 → `application/service/*` 实现 |
| `RedLineModule` | `CommandRedLineService` + `Multibindings<RedLineRule>` 收集 13 个规则 |
| `AsyncModule` | `TaskManager` 单例 |

启动顺序：锁文件检测 → Guice Injector → Flyway 迁移 → Git 检测 → 加载设置 → 显示主窗口。

## 五、跨平台考量

- **Git 可执行文件检测**（BR-41）：Windows / Mac / Linux PATH 查找 + 用户可配置 `app.git-executable`
- **路径分隔符与换行符**：通过 `core.autocrlf` 配置适配
- **启动脚本**：`app-backend/scripts/git-gui.bat`（Windows）/ `app-backend/scripts/git-gui.sh`（Mac/Linux）双版本
- **原生打包**：`jpackage` 生成 `.msi` / `.dmg` / `.deb`（可选）
- **主题跟随系统**：通过 JavaFX 平台主题 API 监听系统主题变化（BR-38）
- **JavaFX 平台依赖**：通过 classifier 区分 `win` / `mac` / `linux`

## 六、安全设计

### 命令红线闭环

```plaintext
领域规则（BR-26~BR-32）
  → audit_log 表（持久化）
  → CommandRedLineService（校验 + 审计）
  → CommandInterceptor（写操作前置拦截）
  → UI 对话框（BLOCK 拒绝 / CONFIRM 确认）
  → 设计文档流程图（本文 3.2/3.3）
  → 测试用例（TC-UNIT-01/02/07/08 + TC-UI-02）
```

七层闭环，红线机制在领域 → 数据 → 服务 → 后端 → UI → 设计 → 测试均有落地。

### 其他安全

- **凭证安全**：通过系统 credential helper（osxkeychain / wincred / manager-core），不明文存储密码（BR-39）
- **路径安全**：仓库路径校验绝对路径 + 存在 `.git`，拒绝 `..` 穿越
- **命令注入防护**：CLI 参数使用 `ProcessBuilder` 参数数组，禁止字符串拼接 shell
- **Secrets 管理**：日志不输出 Git 凭证 / SSH 密钥原文
